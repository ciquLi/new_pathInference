# 实现与产物边界

正式路径：日期清单 → 只读输入核查 → 隔离特征 → 邻居预测 → 前缀/后缀构造 →
255维评分 → 按ρ直接增强或邻居先增强 → 统一路径库R_s → Tree B＋PG → 正常历史GMPI → 独立评价。

`data` 负责精确日期绑定和输入来源。路由日期、公开元数据实际日期和 traceroute
campaign 分开登记。文件存在或历史完成标记不构成内容完整性证明。

`upstream` 包含邻居和路径方法，以及从已验证实现中提取的计算模块。
`implementation` 只保留正式方法使用的定义，没有历史 launcher、质量调参网格或 LLM 审查。
模型文件、特征 schema 和训练源切分由各日期模型 manifest 绑定。

`experiment`管理日期化的增强、训练、检查点冻结、逐AS评测和资源准入。
`prefix_tree`保留公开结构与查询Tree B数值定义，迁移来源和可执行AST身份独立登记。
当前入口不导入实验worktree；完整流程见[rho_workflow.md](rho_workflow.md)。

`core` 保留 PG/GMPI 的数值实现。部分模块保留既有名称，以兼容 PyTorch 1.8
checkpoint 中的模块引用。配置、调度、输入映射和研究协议由外层模块负责。
输入映射仅用于读取；写入始终留在当前 run。exFAT 不支持符号链接和硬链接，
因此不依赖链接拼装数据目录，也不复制整个外部 BGP 语料。

`downstream` 检查训练标签和 PG 局部知识的路径集合哈希，二者必须与 R_s 相同。
模型仅用 BGP 衍生、按源/目的 AS pair 隔离的内部验证选择 checkpoint。

`traceroute` 从 targets-only 清单推断。观测路径直到 checkpoint 和预测冻结后才用于评分。

## 复现记录

`.reproducibility/20261024_unified255_baseline/` 保存整理前源码/模型/输入哈希与结果契约。
原始完整源码及旧 Git 历史位于项目外的 `MetaGMPI_legacy_20261024`。
新实现的运行不能读取该旧工作区，历史绝对路径只能作为来源记录。

## 修改原则

先验证候选、特征数组、评分和最终路径库，再评价下游效果。
有来源证据不足、路径数量不足或模型尚未训练时，保留明确失败状态；
不能降低标准、从正式标签调参、删除 AS 或缩小查询分母来完成运行。
