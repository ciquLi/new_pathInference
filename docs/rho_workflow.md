# 日期化ρ分组流程

## 执行顺序

1. 从`configs/dates/YYYYMMDD.json`读取同日BGP、ASRank、AS关系、PeeringDB、测试AS队列和可选同日上游缓存。
2. 核验规范原始训练流的来源、公开快照、训练源划分、上游模型和255维特征模式。上游训练源采用有效去重原始路径数严格大于10000的全部合格源，按原4:1:1协议划分，正式测试AS单独留出；缓存不满足身份时拒绝使用。
3. 从其他原始训练源独立导出源AS的前向片段，与训练展开库逐条核验后，在独立视图重建该源CSV。源CSV缺失或未收齐时，允许恢复有训练父路径证据的两AS及多跳片段，记录长度分布；不从最终测试路径补片段。原CSV、原RIB、外部数据目录不写入。公开结构U₂与B₁独立于最终路径标签。
4. 计算ρ＝U₂/B₁²。ρ≤1直接使用原模型构造候选并以0.75筛选；ρ>1为全部公开邻居分别构造、评分、按0.90筛选，拼接源AS后检查环路、长度与商业关系兼容性。unknown/conflict关系不按不存在处理；高ρ拼接后不再用源评分器筛选。
5. 冻结全部源增强库，记录每个路径集合哈希。低ρ原1000条最低量仍保留，不触发本轮历史中未实际使用的质量回归补充分支。若需要降低门槛补最低量，记录原门槛、高质量路径数、有效门槛和补入数量；合法正分候选不足时明确失败，不伪造路径。
6. 从公开结构及同一增强库的前缀构造查询Tree B，最多包含S-N-A。ρ>1的公开分支按原B₂(N)>B₁规则展开；ρ≤1保留增强库的模型首跳。HIGH优先，只有缺少HIGH候选的查询才使用UNKNOWN层。训练与PG本地知识共用同一增强库，不能将库外路径混进训练标签。
7. 低ρ保留原PG训练候选，高ρ保留本轮Tree B＋PG训练候选；最终测试查询都使用Tree B＋PG。测试生成器仅消费完整端点清单，输出零标签占位，不读取最终路径。每个查询最多200个候选，这不是增强库总量上限。
8. 正常历史GMPI从头训练，按BGP派生训练AS对划分90%训练、10%验证。10个AS均使用原Huber目标，以自然历史验证Jaccard选择检查点，不额外训练CE模型。架构、优化器、种子和默认训练参数集中在方法配置中。不同日期不共用训练好的GMPI。
9. 每个源的选择冻结后才开放该源最终参考。在独立评测输入副本上填写标签诊断，核验候选、历史、查询顺序的哈希不变，再执行原GMPI推断与独立Jaccard复算。每个AS完成即发布，不等待其余AS，也不把最终测试分数回流选模。
10. 汇报各AS的全量测试分母、Jaccard、完整有序匹配、覆盖率、增强数量、ρ、实际训练配置；同时计算AS等权平均与查询加权平均。

## 日期切换与检查

```bash
bash scripts/run_experiment.sh 20260401 --plan-only
bash scripts/run_experiment.sh 20260401
```

新增日期必须登记自己的原始与派生输入、正式AS队列和快照日期。缺数据时明确报出缺少的文件，不能自动选用邻近月份。`--plan-only`不创建训练任务；`--prepare-only`仅生成独立输入视图；`--upstream-only`核验或完成同日上游模型；`--augmentation-only`在冻结增强库后停止。

现有同日缓存由日期清单的`upstream_cache`显式登记。这是可核验的数据/模型缓存，不是旧实验代码的运行依赖。缓存缺失时走正式`upstream`API独立训练。代码、参数、依赖版本、数据和模型均参与身份记录；不在旧目录上覆盖不兼容产物。

## 调度与故障

同一AS的阶段按训练候选→测试候选→训练/选择→评测准备→评测→复算串行，避免共享缓存竞态；不同AS可并行。训练和候选生成交错。资源配置限制的是最大并发，实际并发由共享内存账本、GPU显存与跨日期GPU槽决定。日志在各运行的`logs/`，状态和结果持续写入文件。

相同输入下已完成阶段校验产物后复用。阶段报错时保留已完成文件，并给出对应日志；中断的训练权重不默认加载为新的初始模型。`--fresh-run`创建新运行而保留旧目录。用户中断时只停止本次调度器自己创建的子进程组。

## 历史结果与统一代码的差异

增强库规则沿用已验证方案：低ρ原0.75，高ρ邻居先增强0.90，低ρ原1000最低量，高ρ无最低量；路径生成沿用原Tree B＋PG数值定义。历史398465、58057实际新增补充路径为0，其他6家也未启用质量回归补充。

历史低ρ八家的最终模型并非同一训练配置：6家Huber、2家CE。原Huber检查点下398465为83.23%、58057为80.22%，同样超过80%。因此新入口对10个AS统一采用正常历史Huber和原内部验证检查点规则，不保留按AS绑定CE模型的特例。这是对历史混合检查点的显式规范化；未经完整运行，不能声称复现历史85.13%。

Tree B的原数值定义以`src/pathveil/prefix_tree/COMPUTATION_PROVENANCE.json`记录来源字节SHA256和可执行AST身份。AST忽略格式与文档字符串差异，保留计算、分支、常量和调用。生产代码无需导入旧实验worktree。
