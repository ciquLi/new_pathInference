# 候选路径独立打分试验

目前范围为 20260201 全部 10 个 AS：19529、328840、16552、32590、34927、42473、49544、58057、199524、398465。复用原前三源试验，逐个 AS，CPU 亲和性 6、7，最多 2 线程，无 GPU。完整范围登记在 `FULL_FEBRUARY.json`，原 `CONFIG.json` 保留冻结参数与最初三源登记，不改写已完成缓存身份。

唯一改变的流程环节是候选路径的最终选择器：原 GMPI 与重新训练的 LightGBM 回归打分器比较。保持原日期的公开证据、已选邻居、递归树、增强库、候选生成器及候选上限 200。复用 GMPI 已固定的 pair-disjoint 训练/验证 CSV，包括候选和 Jaccard 标签，不重做训练候选。标签来自增强路径，是弱监督，并非新引入的原始源 AS 真实观测。

复用增强路径打分模块的 222+33 列特征计算和源隔离证据，但重新训练每个源的模型，不直接使用原增强筛选模型的分数。候选中无法从冻结树匹配到的前缀，明确使用首跳上下文并记录数量，不删除候选。缺失的尾路径频次保持 missing。每个查询总训练权重相同；以验证查询的 top1 Jaccard 选择迭代轮数，最多 500 轮，40 轮无提升停止。特征定义和超参数在读取 test 路径前固定。

已清理的测试候选用原数值 API 在独立目录补生成。不重训邻居模型、不重做增强。测试候选编译只读完整端点清单；模型和预测文件固定后，另一步才读最终参考路径。对照报告完整查询集上的 Jaccard、完整匹配率、候选覆盖率、exact oracle 和 Jaccard oracle。原 GMPI 分数与 oracle 来自冻结结果，候选重新生成后逐查询核对数量和 oracle；如不一致，标记对照未通过，不能直接归因于打分器。

输出：`runs/20260201/candidate_scorer_v1/`。旧三源队列尚在运行时，完整十源表在 `PROGRESS_ALL.md`；接续后统一写入 `PROGRESS.md`。各阶段有独立日志、输入/代码哈希和完成回执。完成阶段经哈希验证后复用，失败停下并写明错误，不循环重跑。

耗时：`TIMINGS.json` 汇总各 AS，后续阶段另有 `as<ASN>/TIMING_<阶段>.json`，分别记录阶段墙钟时间、进程 CPU 时间和峰值内存。训练额外记录纯 LightGBM 拟合时间、训练/验证特征计算时间。早期已完成模型不为计时而重训；历史阶段总耗时含调度轮询延迟，历史拟合只记录日志中开始拟合至模型保存的区间，19529 的原预测耗时仅能给出日志下界，输出恢复时间单独记录。

中断尝试单列于 `INTERRUPTED_ATTEMPTS.json`，不混入成功阶段耗时；总计算开销还应计入这些尝试。中断时尚未持久化的预测需要重新计算，已发布的完整预测通过校验后直接复用。完成核验用 `tools/validation/audit_candidate_scorer.py --rescore`，只对已经冻结并评测的源读取最终标签，核对阶段回执、输入及模型哈希、完整查询分母、候选诊断、计时及独立重评分；输出 `COMPLETION_AUDIT.json`，全部十源通过才标记 PASS。

`resume.py` 是冻结三源运行的结果发布修复：把预测文件哈希/回执发布放到关闭训练标签保护上下文之后，数值预测不变。`full_february.py` 仅扩展原源 AS 准备检查到登记的十源，并添加计时。两者均有独立身份记录，原方法、模型、配置和完成缓存不改写。
